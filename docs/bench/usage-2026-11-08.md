# Usage engine bench, 2026-11-08

Harness: `cargo run --release -p atlas-core --example usage_bench` (release build, Will's PC,
16 logical cores, Windows 11). Two runs are merged below: the real-data run and the synthetic
run. Real-data numbers come from the real Claude projects folder, opened read-only, with the
cache in a scratch folder outside it. No message text is stored in the cache, the report or
this file.

Commands:

```
usage_bench --projects C:/Users/Will/.claude/projects --data <scratch> --runs 3 --out real.md
usage_bench --data <scratch> --gen-huge --append-test --synth 1000000 --out synth.md
```

An earlier run of the same command gave 35.8 s, 15.6 s and 16.2 s (the first pass was slow;
the cause was not established, an OS cache that was not yet warm is the likely one). The run
in the table is the later one. The budget is judged on the median; the 35.8 s outlier is
listed here because it exceeded 30 s.

"2 grew": files belonging to live Claude Code sessions were appended to while the bench
ran. Atlas did not write them: the bench opens nothing under
`projects/` for writing, and the engine's code under `crates/core/src/usage/` has no write,
create, rename or remove call (acceptance 20).

An earlier version of the harness failed the "reads zero bytes" row on the real folder
because live sessions had grown between the index and the rescan. The row now compares bytes
read with bytes grown in the window (equal here), and still requires exactly zero when
nothing grew (the synthetic tree and the fixtures).

### Item usage field names, verified on the real folder (counts only, no text kept)
- 128,510 `tool_use` blocks scanned; 127,273 unique tool ids. 1,237 ids (about 1 %) appear in
  more than one file (a resumed or forked session repeats earlier lines). Tool calls are
  counted each time they appear, so a repeated call counts twice; message tokens are
  de-duplicated by `message.id|requestId`, tool calls are not. Documented caveat.
- Block shape: `message.content[]` entry `{type: "tool_use", id, name, input}`.
- Skill calls: `name == "Skill"`, skill in `input.skill` (`input.args` optional, unused).
- Helper calls: `name == "Agent"` (`Task` handled the same), type in `input.subagent_type`.
  About 2 % of Agent calls have no `subagent_type`; they are recorded as `general-purpose`,
  which is what Claude Code runs.
- Other tools: every `name` is recorded as kind `tool` (MCP tools as `mcp__server__tool`).
- Top real skills: away-mode, ui-ux-pro-max, orchestrate, fewer-permission-prompts,
  design:design-critique. Top helper types: general-purpose, code-reviewer, verifier,
  chore-runner, desktop-app-dev.
- Subagent files: in 1,500 of 1,500 checked, the `agentId` inside the file equals the
  `agent-<id>.jsonl` file name; the line `sessionId` equals the parent folder in 1,498 and
  differs in 2 (a resumed session). Helper spend is rolled up by the line `sessionId`.

## Cost deviation, before and after

Compared with Claude Code's own `cost-state` figure per session (report only).

| | Before | After |
|---|---|---|
| Sessions compared | 224 (1 with unpriced tokens) | 239 (0 unpriced) |
| Median deviation | 0.00 % | 0.00 % |
| Within 2 % | 132 | 145 |
| Mean signed (Atlas higher) | +22.94 % | +21.15 % |
| Worst | 3270 % | 3270.49 % |

Root causes, each proved against real rows:
1. **Unpriced rows (fixed).** Rows with `inference_geo = "not_available"` (about 28 % of
   rows) were left unpriced; they are billed as global. The dated Haiku 4.5 alias was also missing from the seed.
   Both fixed in `pricing.rs` and the seed. `price_tier` is now recomputed when the price
   file changes (`retier_all`), and `includeMissing` defaults to true.
2. **Claude Code 2.1.289 priced with an older table (not an Atlas bug).** Sessions written by
   2.1.289 show Sonnet 5.5 cache reads at 0.1x input and some Haiku 5.5 rows at Opus rates;
   2.1.296 and later match Atlas exactly. Atlas's seed matches the published pricing page.
3. **Token differences in about 52 sessions.** In 39 Claude Code has more tokens than the
   files hold (most likely deleted subagent files); in 13 it has fewer. On token-equal rows
   the published prices match exactly for Opus and Haiku 4.5.

The worst single deviation (3270 %) was not root-caused; it is one session of 239 and the
token counts, not the price table, are the likely difference. Every cost in the app is
labelled "estimate".
