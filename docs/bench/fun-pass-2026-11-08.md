# Fun-pass UI bench, 2026-11-08

Harness: `perf.mjs` (scratch, not committed): launches the real app (debug build, WebView2, Will's PC) over
CDP, 5 rounds alternating base and new, demo fixture data. Base = the app before the fun pass
(`atlas-base.exe`, main 42058ef); new = this branch's tip. Debug builds on both sides, so absolute
numbers are higher than a release build; the comparison is like for like.

| Metric (median of 5) | Base | New |
|---|---|---|
| First contentful paint | 140 ms | 136 ms |
| DOMContentLoaded | 91 ms | 102 ms |
| Load | 91 ms | 126 ms |
| Largest contentful paint | 156 ms | 504 ms (see note) |
| Sessions, first visit to next frame | 9.7 ms | 8.7 ms |
| Toolkit, first visit | 8.8 ms | 11.2 ms |
| Settings, first visit | 5.9 ms | 14.8 ms |
| Dashboard, repeat visit | 4.6 ms | 19.1 ms |
| Long tasks (>50 ms) on any navigation | 0 | 0 |

Notes:
- LCP is not like for like. The base build's largest element was the page heading, painted before any
  data. The new Dashboard's largest element is the 2,928,552 hero number, which only exists once the usage
  data has arrived, so its LCP is the time the data was painted. FCP (first paint of anything) is unchanged.
- Dashboard repeat visit rose from 4.6 to 19.1 ms: the page now carries the heat grid (measured, flexes to
  width), the animated hero, the ridge chart and three more charts. One navigation frame can slip past 16.7 ms
  in a debug build; there are no long tasks. Not measured in release.
- Window resize (a 20 px step per frame, 900 to 2560 and back, Dashboard, debug build): new p50 7 ms, p95 13 ms,
  max 21 ms; base (fixed-width page) p50 4, p95 6, max 8 ms. The cost is the charts redrawing from a
  ResizeObserver and the heat grid re-slicing weeks.
- Sidebar toggle (title bar button): width moves over about 220 ms, frame gaps 2 ms mean and 9 ms max
  in the CDP session (rAF is not vsync-paced there, so this shows no dropped work, not the display rate).
